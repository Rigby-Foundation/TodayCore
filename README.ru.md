# TodayCore

**TodayCore** — экспериментальное сетевое ядро на базе **sing-box 1.15.0-alpha.6**. Проект сохраняет архитектуру и формат конфигурации sing-box, добавляя отдельные современные клиентские возможности, перенесённые из **Xray-core 26.9.9**.

> [!WARNING]
> TodayCore находится в beta-стадии и развивается сообществом. У проекта нет фиксированного графика релизов, гарантированной совместимости или коммерческой поддержки. Проверяйте каждое обновление перед использованием в рабочем окружении.

## Зачем нужен TodayCore

Цель проекта — совместимость sing-box с актуальными конфигурациями Xray без попытки полностью скопировать Xray. Рассматриваются только современные и практически полезные функции; устаревшие и legacy-протоколы намеренно не входят в область проекта.

Кодовая база называется **TodayCore**, но её основой является **sing-box 1.15.0-alpha.6**.

## Что добавлено поверх sing-box

### Исходящий транспорт XHTTP

Клиентский транспорт Xray SplitHTTP/XHTTP перенесён из Xray-core 26.9.9.

Реализовано:

- режимы `packet-up`, `stream-up`, `stream-one` и `auto`;
- работа через HTTP/1.1 и HTTP/2;
- размещение метаданных сессии в path, query, header или cookie;
- отправка uplink-данных в body, header или cookie;
- X-Padding с настраиваемыми размещением, ключом, заголовком и обфускацией;
- стандартные заголовки, похожие на браузерные;
- настройки повторного использования соединений и запросов XMUX;
- отдельные `downloadSettings`;
- keep-alive для HTTP/1.1, очередь загрузки и split-connection.

XHTTP доступен только как **исходящий клиентский транспорт**.

### Совместимость с современным REALITY

Клиент REALITY обновлён для совместимости с серверами Xray-core 26.9.9:

- восстановлен гибридный key share `X25519MLKEM768` перед обычным `X25519`;
- сохранён X25519 key share, необходимый для аутентификации REALITY;
- в REALITY session ID указывается совместимая версия клиента `26.9.9`;
- устранён типичный fallback на целевой сайт, который проявляется как `reality verification failed` на серверах с требованием современного клиента.

При использовании REALITY с uTLS это поведение включается автоматически.

### Постквантовое шифрование VLESS

TodayCore содержит экспериментальный клиентский перенос VLESS Encryption из Xray:

- `mlkem768x25519plus`;
- режимы `native`, `xorpub` и `random`;
- рукопожатия `1rtt` и `0rtt`;
- профили padding;
- 32-байтовые публичные ключи X25519 и 1184-байтовые ключи ML-KEM-768;
- цепочки relay-ключей.

Реализация пока работает только на стороне **клиента/outbound** и считается экспериментальной до прохождения более широкого тестирования совместимости.

## Статус переноса функций

| Функция Xray | Статус в TodayCore | Примечание |
| --- | --- | --- |
| XHTTP outbound/client | Перенесено | HTTP/1.1 и HTTP/2 |
| XHTTP `packet-up` | Перенесено | Только клиент |
| XHTTP `stream-up` | Перенесено | Только клиент |
| XHTTP `stream-one` | Перенесено | Только клиент |
| XHTTP metadata placement и X-Padding | Перенесено | Имена полей совместимы с Xray |
| XHTTP XMUX | Перенесено | Управление переиспользованием соединений и запросов |
| Совместимость REALITY с `X25519MLKEM768` | Перенесено | Автоматически для поддерживаемых uTLS fingerprints |
| VLESS Encryption `mlkem768x25519plus` | Экспериментально | Только client/outbound |
| XHTTP inbound/server | Не перенесено | Явно отклоняется при обработке конфигурации |
| XHTTP через HTTP/3 | Не перенесено | Используйте `h2` или `http/1.1`; проекты используют несовместимые форки QUIC |
| Browser dialer из Xray | Не перенесено | Интеграции browser dialer нет |
| REALITY `mldsa65Verify` | Не перенесено | Не реализовано |
| REALITY `spiderX` | Не перенесено | Не реализовано |
| FinalMask | Не перенесено | Не реализовано |
| VLESS Encryption inbound/server | Не перенесено | Реализация только для клиента |

## Конфигурация

TodayCore использует JSON-формат конфигурации sing-box. Описание и примеры специфичных для TodayCore возможностей находятся в файле:

- [Расширения TodayCore и примеры конфигурации](docs/todaycore-extensions.md)

Оригинальная документация sing-box сохранена в каталоге [`docs/`](docs/). Для полей, которых нет в отдельном руководстве TodayCore, используйте документацию sing-box 1.15.

## Сборка

### Требования

- Go **1.25.5** или совместимая более новая версия;
- Git;
- `make` для стандартного процесса сборки.

### Стандартная сборка

```bash
make
```

Установка в `$GOBIN`:

```bash
make install
```

Выбранные build tags можно передать через Makefile:

```bash
TAGS="with_quic with_utls" make
```

Стандартные build tags и необходимые linker flags находятся в `release/DEFAULT_BUILD_TAGS*` и `release/LDFLAGS`. Если вам не нужны особые платформенные настройки, предпочтительно использовать стандартную цель `make`.

## Статус разработки и участие

TodayCore поддерживается **исключительно на добровольной основе**. Разработка может надолго приостанавливаться. Нет обещаний, что изменения из новых версий sing-box или Xray будут переноситься немедленно.

Если вы хотите, чтобы проект активно развивался, проявляйте инициативу:

1. тестируйте TodayCore с актуальными серверами Xray;
2. сообщайте о воспроизводимых проблемах совместимости;
3. прикладывайте логи, версии клиента и сервера, а также очищенную от секретов конфигурацию;
4. добавляйте тесты протокола и wire format;
5. отправляйте pull request с небольшим и понятным изменением.

Полезные коммиты и pull requests — лучший показатель реального интереса к продолжению разработки. Вклад сообщества приветствуется и напрямую влияет на скорость развития проекта.

По возможности делайте pull requests небольшими, описывайте поведение, которое переносится, и добавляйте ссылку на соответствующую реализацию или спецификацию Xray.

Проект работает с низкоуровневой сетью, криптографией и экспериментальной совместимостью протоколов. Успешная сборка не означает, что код прошёл аудит безопасности. Не публикуйте приватные ключи, UUID, ключи REALITY или полные production-конфигурации в отчётах об ошибках.
